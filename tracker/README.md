# 1-Y / KPω 进度看板

用浏览器打开 [index.html](index.html)。页面内嵌数据、样式和交互，不需要联网或安装依赖。也可从工作区本地预览服务访问 /kp-simplified-verification/tracker/。

## 六个视图

- **证明梗概**：六阶段、当前主要依赖链、并行负责人和最终命题范围。
- **任务看板**：默认未验收任务，可筛支线/状态/负责人/关键词；卡片含前置、独占文件、验收及证据。
- **数学依赖图**：87个节点，箭头为前置→使用者；可缩放、筛支线或聚焦完整上下游。
- **并行批次**：从当前实现继续的P0–P8，可复制具体subagent指令，不重派已有成果。
- **Lean模块图**：直接读取当前源码imports，搜索模块/声明，查看直接邻域或完整前置/使用者。
- **核验证据**：冻结阶段、当前指纹、审计边界和更新命令。

## 状态口径

“已核验”要求代表性源码及依赖匹配有效阶段证据。模块变化只保留未受影响任务的旧证据；整个根审计是否过期另行显示。

“已交付·待集成”是已检查冻结代码的交接报告，绑定源码/依赖、产物和日志指纹；不冒充新阶段检查或公理审计。指纹变化会使交付状态失效。

“正在实现”可以是先做局部工作，未具备的前置仍在详情显示。“可启动”不代表已启动agent。负责人和运行说明是快照，不会自动轮询进程。

个人备注仅存于浏览器localStorage，可导出JSON，不改变数学核验状态。看板不允许拖拽伪造“证明完成”。

## 更新

```bash
cd /home/dev/ggg/kp-simplified-verification
python3 tracker/refresh.py
```

默认更新只读取源码/imports/指纹及既有证据，输出index.html、data.json、DEPENDENCIES.md和当前任务指令，不调用Lean。浏览器刷新页面即可看到新快照；它不是实时后台监控。

plan.py维护任务/依赖/唯一文件，deliveries.json记录冻结交付。数学前置与实际import不是一回事，因此同时提供两张图。退休任务的旧指令会在刷新时移除。

root冻结一批后才运行verify-local-stage.py --root KP1Y和refresh.py --audit，只检查受影响模块并复用依赖，不运行lake build。
